## 父单

PRD: [2.4.0.md](../.PRD/2.4.0.md) — to-test 红绿灯验收测试（TDD 驱动）

## 要做什么

把 `to-test` 的 **red 阶段**打通成一条端到端可用的薄片：给定一个 issue，技能能在编码前按 issue 验收标准生成红绿灯清单、启动可访问的页面、按浏览器能力阶梯执行用例并落红证据；无自动化能力时标黄并附人工步骤。

端到端行为：

- 调用 `/to-test red` 后，issue 文档出现固定章节：头部 YAML 摘要（prd_version / issue / phase / cases / generated_at）+ 每用例一张 Markdown 卡（id / criterion / todo / precondition / steps / assert / executor / red_evidence / light / yellow_reason）。
- red 阶段能自动复用已运行实例，或后台拉起 `dev`/`preview` 并轮询到就绪；超时才询问用户 URL。
- 浏览器执行器按阶梯探测（项目内 Playwright → 浏览器类 MCP → orca-cli / computer-use → 人工），命中后记录执行器名称与版本。
- 失败证据落 `.TEST/<PRD版本>/<issue>-<时间戳>/`（截图 + 日志），issue 清单只记路径与失败摘要。
- 缺少红证据的用例标记作废；非 Web 项目自动退化为原「问用户是否通过」回收模式并说明原因。
- 同步更新 `packages/omz/skills/to-test/SHOWCASE.zh.md`、`SHOWCASE.en.md`（red 用法示例）、`src/constants/skills-meta.ts` 描述、`packages/dsh-plugin-zerone/skills/to-test/SKILL.md`（内嵌副本）。

## 验收标准

- [ ] `/to-test red` 在真实页面项目上能生成含 YAML 摘要与用例卡的 issue 清单，字段完整
- [ ] 应用启动策略生效：优先复用已运行实例，无实例时后台拉起并轮询就绪，超时才询问 URL
- [ ] 浏览器阶梯探测命中后记录执行器与版本；四级全不可用时的用例标黄并附可照做的人工步骤
- [ ] 红证据落盘 `.TEST/<版本>/<issue>-<时间戳>/`，issue 清单记录路径、执行器、时间、失败摘要
- [ ] 缺红证据的用例被标记作废，不能进入绿阶段判定
- [ ] 非 Web 项目自动退化为原问询式回收，并在报告说明原因
- [ ] SHOWCASE.zh/en、skills-meta 描述与 DSH 插件内嵌副本同步为 red 阶段语义

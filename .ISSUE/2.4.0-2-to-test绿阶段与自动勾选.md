## 父单

PRD: [2.4.0.md](../.PRD/2.4.0.md) — to-test 红绿灯验收测试（TDD 驱动）

## 要做什么

在 red 阶段之上补齐 **green 阶段与自动勾选**，并把机制文档同步到绿灯语义，形成可完成的 TDD 闭环：

- `/to-test green` 重放 issue 内清单，逐用例判定当前灯（绿 / 黄 / 红）；缺红证据的用例作废，不得转绿。
- 全绿时自动勾选该 issue 的验收标准，并同步勾选对应 PRD TODOQ；存在黄/红时一律不勾。
- 红灯输出返工单（失败用例、证据、期望、交给 `/to-coding`）；黄灯输出人工验证步骤，用户确认后才可转绿。
- to-coding 修复后可自跑清单自测，但最终绿由 to-test 判定；建议 3 轮后强制人工。
- 跨 issue 主干流程清单维护在端到端验收 issue；不存在该 issue 时只报缺口，不自动创建。
- 记忆引导保留，触发条件改为「全绿且无黄」。
- 机制同步：`workflow.md`（根 + `packages/omz`）step4 扩为逐 issue TDD 循环、step5 收口为全流程与 PRD TODO 对账并移除「未验收禁止打勾」；`to-coding` 取消人工勾选权；根与包内 `AGENTS.md` 技能条目、`omz-governance` 步骤表、`permission.md` 增加跑项目脚本/启动 dev server 授权项；根 `.gitignore` 增加 `.TEST/`。

## 验收标准

- [ ] `/to-test green` 能重放清单并输出绿/黄/红统计与逐条证据
- [ ] 全绿时自动勾选 issue 验收标准与对应 PRD TODOQ；有黄/红时不勾
- [ ] 缺红证据的用例在绿阶段被判作废，不参与全绿判定
- [ ] 红灯输出可交接的返工单；黄灯输出人工步骤与确认记录，确认后才可转绿
- [ ] `workflow.md`、`to-coding`、`AGENTS.md`、`omz-governance`、`permission.md`、`.gitignore` 同步为绿灯语义，旧「未验收禁止打勾」措辞已移除
- [ ] 记忆引导仅在「全绿且无黄」时触发
- [ ] 端到端验收 issue 缺失时只报缺口，不自动创建 issue

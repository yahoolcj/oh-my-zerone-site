# 2.3.0

## dsh-plugin-zerone（OMZ × DeepSeek Harness 内置插件）

> 类型：新增

### 概述

OMZ（oh-my-zerone）从"编辑器内容协议"扩展为 DeepSeek Harness（DSH）的内置插件能力。交付一个 cordis 插件包 `@vigalai/dsh-plugin-zerone`（npm 独立分发 + dsh-desktop 捆绑，共用同一包），实现：

- **零落盘内置**：15 个 SDD 技能内嵌于插件包，经 `ctx.skills.register()` 全局注册（运行时 rank 250，模型与用户命令双入口），技能文件不写入用户系统任何目录。
- **ZERONE 模式**：随包内置 agent preset（`config/agent-presets/zerone/`），为 DSH 标准模式完整副本叠加 OMZ 人格（AGENTS.md 全文 + 机制红线）与机制提示段；可选模式，不改变默认设置。
- **仓库级机制**：进化授权 / [用户确认] / review 以对话级流程纪律落地（红线常驻 persona，`omz-governance` 运行时技能承载流程细节），DSH 沙箱与审批栈兜底；仓库只保留数据资产（memory.md、knowledge/、evolution-log.md、.PRD/、.ISSUES/），由模型首次使用时自动创建，introduction.md 由 setup-omz 按需生成。

关键架构决策见 `docs/adr/0001-omz以插件加preset接入dsh.md`，DSH 平台机制事实见 `docs/knowledge/dsh-platform.md`。

### 数据模型 Schema

#### 插件包目录结构
| 路径 | 类型 | 必填 | 说明 |
|------|------|------|------|
| package.json | 文件 | 是 | name: @vigalai/dsh-plugin-zerone；exports 暴露 main 与 preset 资源 |
| lib/index.js | 文件 | 是 | cordis 插件入口（name/inject/Config/apply）；apply 内 ctx.skills.register() 注册 16 项技能 |
| config/agent-presets/zerone/preset.yml | 文件 | 是 | 展示元数据（name/description/order） |
| config/agent-presets/zerone/agent.cordis.yml | 文件 | 是 | ZERONE 模式组合（standard 副本 + 增量） |
| skills/**/SKILL.md | 目录 | 是 | 15 个技能资源 + omz-governance 内容资源 |

#### SkillRegistration（ctx.skills.register 参数）
| 字段 | 控件 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|------|--------|------|
| name | - | string | 是 | - | kebab-case 技能名（如 to-prd） |
| description | - | string | 是 | - | 模型目录/命令面板可见描述 |
| content | - | string | 是 | - | SKILL.md 正文（含 @author/@group 等） |
| resources | - | Record<string, string> | 否 | - | 嵌套资源（如 grill-me-ui/agents/openai.yaml） |
| invocation | - | { modelInvocable, userInvocable } | 否 | true/true | 默认双入口，/to-* 出现在命令面板 |

#### preset.yml
| 字段 | 控件 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|------|--------|------|
| name | - | string | 是 | - | ZERONE |
| description | - | string | 是 | - | 标准能力 + SDD 工作流/进化/审查机制的 OMZ 人格 |
| order | - | number | 否 | - | 模式列表排序 |

#### persona 配置（agent.cordis.yml 行）
| 字段 | 控件 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|------|--------|------|
| id | - | string | 是 | persona | 行标识 |
| name | - | string | 是 | @deepseek-ai/dsh-persona | 插件名 |
| config.text | - | string | 是 | - | AGENTS.md 全文 DSH 化 + 机制红线 |
| config.complete | - | boolean | 否 | false | 是否完整提示词 |
| config.includeRuntimeContext | - | boolean | 否 | true | 是否注入运行时上下文（{{model}}/{{cwd}}） |

### 页面交互

- 不涉及前端页面开发；DSH GUI 行为：
  - 模式列表出现 **ZERONE**（随包内置 preset，`agentPresets.roots` 指向包内目录）
  - 命令面板出现 `/to-prd`、`/to-coding`、`/setup-omz` 等 16 个技能命令（userInvocable）
  - 模型目录出现全部技能摘要（modelInvocable），按需加载正文
- 安装动作：
  1. `dsh plugin --profile <name>` 安装 npm 包
  2. profile 的 `cordis.patch.yml` 增加一行：`agentPresets.roots` 指向 `node_modules/@vigalai/dsh-plugin-zerone/config/agent-presets`
  3. dsh-desktop 捆绑场景：依赖 + 预置 patch，开箱即得

### 扩展性要求

- 技能清单注册表驱动：增删技能只改插件内注册代码与资源，不动平台
- ZERONE = standard 副本 + 增量：standard 升级时需同步合并差异到 ZERONE 组合文件
- 与用户已有技能目录（~/.agents/skills、项目 .dsh/skills）同名技能：运行时 rank 250 覆盖用户根，项目根可覆盖运行时 —— 冲突行为明确
- 插件包内 preset 的行解析：包名从 host 组合解析，相对路径从 preset 自身目录解析；preset 内服务行必须位于 isolate realm group 内
- 仓库不再放置 AGENTS.md（避免与 persona 双重注入）；codex/cursor 等其他编辑器如需 OMZ 仍走原安装路径（多编辑器兼容后续单独评估）

### 用户故事

1. 用户打开 dsh-desktop（捆绑版），模式列表出现 ZERONE，切换后会话获得 OMZ 人格：自主进化 + SDD 工作流 + 进化授权 + 用户确认机制
2. 用户在命令面板输入 `/to-prd`，模型按技能流程把当前讨论整理成 `.PRD/<version>.md`
3. 模型发现可沉淀的项目事实，发起 `[进化申请-知识库]`，用户对话确认后写入 `docs/knowledge/`；未确认前不落盘
4. 用户首次在 DSH 打开一个新仓库并切换到 ZERONE 模式，模型自动创建 `docs/agent/memory.md` 等数据资产，并按需执行 setup-omz 生成 `docs/agent/introduction.md`
5. 用户通过 `dsh plugin` 在另一台机器安装插件包，同样获得 ZERONE 模式与全部技能，无需拷贝任何文件
